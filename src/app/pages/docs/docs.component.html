Frontend overview

  • Features: authentication with JWT storage, admin-aware routing, starship browsing with search/filter, favorites, and responsive glass UI.
  • Stack: Angular 19 standalone components, TypeScript, SCSS, router + HttpClient, JWT interceptor.
  • Auth flow: login/register ➜ backend issues JWT ➜ stored in localStorage ➜ interceptor adds Authorization header ➜ guards gate protected routes ➜ navbar reacts to session state.

Getting started locally

  1. Install prerequisites: Node.js 20+, npm 10+, and optionally the Angular CLI.
  2. Install deps: npm install.
  3. Create src/environments/environment.ts and environment.prod.ts with your API base URL.
  4. Run the dev server: npm start (served at http://localhost:4200).
  5. Tests & builds: npm test and npm run build.

App structure: src/app/core for guards/services/interceptors, src/app/pages for features, and src/app/shared for reusable UI.

Backend quick facts

  • Platform: ASP.NET Core 8 + Entity Framework Core.
  • Database: SQLite when containerized; migrations + seeding supported.
  • Auth: Identity + JWT with roles (user/admin).
  • Key endpoints: /api/starship (data), /api/auth/login, /api/ai/ask (OpenAI-powered responses).

Docker workflow (backend)

  1. Build image: docker build -t starshipapi . from the StarShipApi folder.
  2. Persist DB: create volume docker volume create starshipsdb; SQLite lives at /app/starships.db.
  3. Seed: docker run --rm -it -v starshipsdb:/app -e ASPNETCORE_ENVIRONMENT=Production -e OpenAI__Key="..." starshipapi dotnet StarShipApi.dll --seed.
  4. Run API: docker run -d -p 8080:8080 -v starshipsdb:/app -e OpenAI__Key="..." --name starshipapi-container starshipapi.
  5. Reset: remove the volume (docker volume rm starshipsdb) to wipe data.

The image uses a multi-stage Dockerfile, applies migrations during build, and delegates startup/seeding logic to entrypoint.sh.

Azure deployment (containerized backend)

  1. Build + tag: docker build -t starshipapi . then docker tag starshipapi <acr>.azurecr.io/starshipapi:latest.
  2. Push to ACR: login (az acr login) then docker push.
  3. App Service config: clear linuxFxVersion if needed, then set container with --docker-custom-image-name and admin credentials (avoid managed identity flags).
  4. Database: SQLite persists at /home/site/wwwroot/starships.db; production auto-migration + seeding runs inside Program.cs.
  5. Redeploy flow: rebuild, retag, push, then az webapp restart; check logs via az webapp log tail.

On Azure, command-line args and entrypoint.sh are ignored, so the app self-migrates/seeds on startup.

Environment keys

  • Frontend: set apiUrl in the Angular environment files to point at your backend host.
  • Backend: set OpenAI__Key for AI endpoints and seeding, plus any JWT/Identity secrets configured in the API.
